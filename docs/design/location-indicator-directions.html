Active location indicator — Visitas

Five directions for telling the user, without alarming them, that location is in use during the only two moments the app actually tracks: the visits map and the Nearby visits filter in the list. This is not a permission request — that is already PermissionRationaleSheet. It is a state indicator. The mockups use the app's real theme and the existing strings from values/strings.xml.

DIRECTION A

Floating pill that collapses

A 28dp pill that appears, says what is happening for four seconds, then shrinks down to just the dot. It floats above the content — no layout is pushed — and it is the same composable in both scenarios, with only the anchor changing: above the FloatingBar in the list, at TopStart over the map.

The 400ms entry delay is the detail that decides how this feels: without it, opening and closing the map quickly makes the pill flash. The 4s dwell is long enough to read, short enough not to become furniture.

For

  • One composable serves both scenarios — the only difference is the Alignment.
  • Nothing reflows: it floats, so the list and the SummaryCard stay put.
  • The collapsed state is honest — the text goes, the presence stays. It is the pattern Maps and Waze already taught users.
  • Big enough for TalkBack to find, and big enough to become tappable later (e.g. open the filter).

Against

  • It covers pixels; in the list it must respect floatingBarBottomPadding so it does not collide with the FAB.
  • Two states (expanded/collapsed) means more animation logic and another screenshot-test case.
  • On short screens it overlaps part of a card while expanded.

Where it would live: a new ui/views/LocationActiveIndicator.kt, placed in a Box in VisitListScreenContent and inside the Box of VisitMapSheet.

Recommendation: Direction A — the floating pill that collapses

The deciding reason is structural rather than aesthetic: the map is a full-screen BasicAlertDialog with no app bar and no FloatingBar. Directions B, C, D and E all anchor to chrome that exists only in the list, so each needs two implementations — two composables, two sets of screenshot tests, two chances to drift apart. A is the only one that is one composable with two anchors.

It is also the only one that resolves the tension in the brief. "Gentle" has two halves: it has to be noticed the first time, and it has to get out of the way afterwards. The banner (B) is noticed and never leaves. The icon (C) and the badge (E) are out of the way from the start — they were never noticed. Inline (D) is elegant but scrolls away, so the notice is absent exactly while tracking continues. The pill is seen, is read, and then shrinks to a dot that stays: presence remains, the noise goes.

Decorative dotclearAndSetSemantics {}, so it does not become a stray node in the tree.

Optional reinforcement

A and D do not compete. If a second level of explanation is wanted, D's supporting text in the Nearby visits header answers "why does this section exist?", while the pill answers "location is on right now". Those are different questions. It is just not worth shipping both in the same release — measure whether the pill alone already covers it.
